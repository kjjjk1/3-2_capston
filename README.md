# DT Sniper

두 링크 연동 수정본입니다. GitHub Pages는 자체 추정만, Render는 경로 API ON/OFF를 지원하며 양쪽 모두 Render를 통해 같은 DB를 사용합니다. 업로드·환경설정·검증 범위는 [DUAL-HOST-SETUP.md](DUAL-HOST-SETUP.md)를 먼저 확인하세요.

참여자별 출발지와 이전 누적 상대 부담을 고려해 모임 장소를 추천하는 웹 서비스입니다. 대중교통 경로 API 예상시간을 사용하며 실제 이동시간을 측정하지 않습니다.

## 무료 서버 배포

[DEPLOYMENT.md](DEPLOYMENT.md)를 따라 Render Free + Supabase Free로 배포합니다. render.yaml은 Free 서비스이며 영구 디스크를 생성하지 않습니다. DB 연결은 서버 환경변수 DATABASE_URL로만 전달합니다. 비밀번호와 API 키를 GitHub에 올리지 마세요.

- Node.js 24 권장.
- 의존성 설치: `npm ci`
- 빌드: `npm run build`
- 실행: `npm start`
- 검증: `npm run build` 후 `npm test`
- 상태 확인: `/healthz`

DATABASE_URL이 있으면 PostgreSQL과 DB 사진 저장소를 사용하고, 없으면 기존 로컬 SQLite와 파일 저장소를 사용합니다. 무료 Render 설정은 REQUIRE_REMOTE_DB=true이므로 DB 연결 없이 임시 저장소로 실행하지 않습니다. 최초 DB 구조 생성과 공개 교통망 데이터 가져오기는 자동입니다. 기존 PC 기록은 자동 이관되지 않습니다.

## 분석 흐름

정류장·노선 DB → 중앙 범위 후보 탐색·사전 평가 → 선별 후보의 경로 API 예상시간 확인 → 누적 공정성/이동 효율/개인 부담 완화 대안 → 장소 확정 시 이동 기록 저장. 후보 수와 조회량은 모임 조건·공급자·설정에 따라 달라집니다. 조회한 후보 안의 비교이며 매번 누적 불균형이 감소한다고 보장하지 않습니다.

무료 서버는 미사용 시 절전될 수 있으므로 발표 직전에 접속·분석을 확인하세요. 모임과 사진은 외부 DB에 보관됩니다. 사진도 무료 DB 용량을 사용합니다.

## 경로 API ON/OFF

모임 관리에서 ON(서버 키로 경로 검증) 또는 OFF(교통 DB 자체 추정)를 선택합니다. 키 없는 ON은 차단되고 자동 OFF 전환은 없습니다. 키는 Render Environment에 나중에 등록해도 됩니다. OFF 결과·기록에는 API 미검증을 표시하며, 확정한 정기 기록은 누적 부담에 반영됩니다. 상세 안내는 DEPLOYMENT.md를 참고하세요.

## 2026-11-19 예시 모임 수정

홈의 모임 만들기 아래에서 4명 예시 모임을 열 수 있습니다. 예시는 홍길동(한밭대), 김철수(충남대), 이영희(대전대), 박민수(한남대)의 근처 실제 정류장을 사용합니다. 클릭 시 모임 관리로 이동하며 자동 분석하지 않습니다. 참여자·출발지와 API ON/OFF를 확인한 뒤 공정한 중간지점 찾기를 눌러 분석합니다. 예시 기본 설정은 OFF입니다. 서버의 HTML 오류 응답은 JSON 파싱 오류 대신 접속 주소·서버 상태 안내로 표시합니다. Render가 중지돼 있으면 재개해야 모임 생성이 가능합니다.

## 링크·방 ID 기반 공유 모임

기존 모임의 링크나 방 ID를 아는 사용자는 별도 참여 토큰·복구 코드 없이 모임을 함께 사용할 수 있습니다. 모든 참여자의 이름·출발지 조회와 수정, 참여자 추가·제거, 사진·교통수단 설정 변경, 분석·장소 확정·기록 조회가 가능합니다. 화면에서 개인 권한 복구 대신 공유 모임 동작을 안내합니다. 다른 방의 참여자 ID를 이용해 수정할 수는 없습니다.

기존 참여자 ID·이동 기록·토큰 해시는 유지합니다. 기존 기록의 개별·전체 삭제와 생성자 복구 코드 발급에는 기존 생성자 권한이 필요합니다. 모임 생성자 권한 자체를 새로 발급하거나 DB 권한 해시를 교체하지 않습니다. DT Sniper 별칭은 지정한 기존 시연 방으로만 연결하며, 일반 모임 이름 검색은 지원하지 않습니다.

## 전체 누적 부담의 보상·균형 평가

이전 누적 부담이 있는 정기 모임은 조회한 모든 후보를 개인별 보상으로 비교합니다. 기본 점수는 |이전 누적 부담| − |예상 누적 부담|이며 양수/음수 모두 0에 가까워지면 가점, 멀어지면 감점입니다. 과거의 표준편차 개선 필수 조건과 0.5분 동률 범위는 적용하지 않습니다.

각 후보에서 기본 점수 합(netGain), 악화량 합(totalWorsening), 최대 개인 악화, 0을 지나간 반대편 부담(overshoot), 전원의 예상 최대−최소 격차를 계산합니다. 악화되는 참여자가 없는 후보가 있으면 먼저 비교하고, 후보 순위 점수는 netGain − totalWorsening − overshoot − max(0, 이후 격차 − 이전 격차)입니다. 감점 항의 계수는 각각 1로 설정한 정책 선택입니다. 이후 최대 개인 악화·누적 격차·표준편차·평균 이동시간 순으로 동률을 비교합니다. 따라서 일부 개선이 다른 사람의 반복 손해를 가리는 것을 제한하며, 표준편차는 보조 지표로 함께 표시합니다.

중앙 후보로 보상이 어려우면 기존 부담자 방향의 확장 탐색을 활용하며, 자체 추정 후보 선별·최종 추천·추가 탐색 후보에 같은 보상 기준을 반영합니다. API 조회 후보 수와 호출 한도는 유지합니다. 적합한 보상 후보가 없어도 결과·확정은 허용하되 보상 실패로 표시합니다. 총량만 개선되고 악화자가 있으면 부분 보상으로 표시합니다. 분석 결과 화면의 개인별 보상 상세 표는 표시하지 않습니다. 이동 기록의 회차별 개인 부담 통계는 유지합니다. 가능한 후보 내 비교일 뿐 전원 보상이나 격차 감소를 보장하지 않습니다.

최대 부담자 보호 모드, 첫 모임·일회성 모임·개인 배려 요청 호환성은 유지합니다. 모임명 수정은 기존 방 ID·참여자·기록을 유지하며, 공유 접속에서는 길찾기 출발 참여자를 선택해 카카오맵을 열 수 있습니다. 길찾기 링크 생성 자체는 경로 API를 호출하지 않습니다.

## 분석 시간 진단

분석 결과 하단의 분석 소요시간을 펼치면 DB 조회·저장, 후보 생성·선별, 공정성 평가·추가 후보 계산, 경로 API 응답 대기, 기타 처리 시간을 볼 수 있습니다. API 요청별 후보/참여자 순서, 소요시간과 성공·실패도 표시합니다. 추가 API 호출 없이 기존 분석을 측정하며, 스트림이 시작된 분석의 실패·취소는 Render 로그의 analysis_timing 이벤트로 확인합니다. 로그에는 비밀키·토큰·요청 URL·이름·출발 좌표를 기록하지 않습니다.

측정 범위는 서버의 분석 핸들러 진입부터이며 Render 콜드 스타트, 핸들러 이전 인증·연결, 브라우저 전송·화면 표시 시간은 포함하지 않습니다. 화면 수치는 결과 전송 직전까지, 로그 수치는 마지막 분석 잠금 정리까지 포함하므로 조금 다를 수 있습니다. 병렬화나 캐시 최적화는 아직 적용하지 않습니다.
